# Configure and operate the app

[Docs](README.md) · [Quickstart](quickstart.md) · [Security](security-and-privacy.md)

The bundled Compose stack is a local, single-user deployment. `setup.sh` creates
`.env`; [`docker-compose.yml`](../docker-compose.yml) controls which variables
reach each container. Standalone CLI/library configuration is separate.

## Common Compose settings

| `.env` variable | Default | Purpose |
|---|---|---|
| `FRONTEND_PORT` | `28080` | Browser and same-origin API proxy |
| `BACKEND_PORT` | `28000` | Direct HTTP API |
| `NEO4J_HTTP_PORT` / `NEO4J_BOLT_PORT` | `27474` / `27687` | Neo4j admin/driver access |
| `BIND_ADDR` | `127.0.0.1` | Local interface; affects all published ports |
| `NEO4J_PASSWORD` | Required | Generated by setup |
| `GRAPH_HMAC_KEY` | Required | Generated stable key for configuration redaction |
| `AUTH_ENABLED` | `false` in Compose | Require API bearer authentication when enabled |
| `ALLOW_ANONYMOUS_READS` | `true` in Compose | With auth enabled, allow reads without a token |
| `API_TOKEN` | Empty | Shared API credential when auth is enabled |
| `ALLOWED_GIT_HOSTS` | `github.com` | Allowed ingestion clone hosts, comma-separated |
| `GITHUB_TOKEN` | Empty | Optional server-side GitHub clone credential |
| `MAX_SCOPE_REPOS` | `20` | UI repository selection cap |
| `INGEST_WORKERS` | `2` | Concurrent repository jobs; not per-repo parser parallelism |
| `WRITE_BATCH_SIZE` | `500` | Rows per Neo4j write batch; timeout batches split and retry |
| `NEO4J_HEAP` / `NEO4J_PAGECACHE` | `2G` / `1G` | Database memory budgets |
| `TRACEKITE_CORS_ORIGINS` | Empty | Extra browser origins; same-origin proxy needs none |

After changing container environment values, recreate the affected service with
`docker compose up -d backend` or the appropriate service. Restarting an existing
container alone does not change its environment.

The backend's `GRAPH_DETAIL_NODE_LIMIT` defaults to 80. **In 0.2.0 the Compose
file does not forward this variable**, even though `.env.example` lists it.
To change it, add a `compose.override.yaml`:

```yaml
services:
  backend:
    environment:
      GRAPH_DETAIL_NODE_LIMIT: "120"
```

Then recreate the backend. `/api/config` exposes the values the UI consumes;
reload the browser after changing them. Settings for running the backend outside
Compose are defined in [`config.py`](../backend/tracekite/config.py); its auth
default is enabled, unlike the local Compose override.

## Reuse an existing stack

Use the same Compose project name and volume mappings used at installation.
Changing them can make existing data appear missing or conflict with fixed
container names. Before an upgrade:

```bash
docker compose ls
docker ps --format '{{.Names}}\t{{.Ports}}'
docker volume ls
```

For installations with custom project names, use the same `docker compose -p`
value on subsequent commands. The [migration guide](rename-migration.md#docker-volumes)
explains the four `TRACEKITE_*_VOLUME` overrides. Do not start a second Neo4j or
remove volumes to fix a port/container-name conflict.

## Data and updates

Named volumes hold Neo4j data/logs, cloned repositories, and backend state.
`docker compose stop` retains them. `docker compose down --volumes` deletes
persistent data and is not an upgrade step.

Hosted refreshes replace one repo's stored source graph; successful ingests
queue an estate link run. The job queue serializes linking and deletion against
ingestion. Jobs are in-process; after a restart, interrupted work is reported
failed and should be inspected/requeued. See [jobs and freshness](api.md#jobs-and-freshness).

No server watcher refreshes a repo just because its remote Git head changed.
Use the UI refresh, an API client, or your own scheduler.

## Tune matching rules

[`config/`](../config/) contains the versioned matching configuration:

| File | What it controls |
|---|---|
| `confidence.yml` | Resolver confidence tiers, active floor, fusion and matching limits |
| `service_aliases.yml` | Explicit service identity and domain rules |
| `internal_namespaces.yml` | Internal package/image boundaries |
| `vendor_catalog.yml` | Classify external host declines; does not invent vendor edges |
| `promotions.yml` | Persisted operator promote/reject decisions |
| `repos.yml` | Repository metadata; declaring `auto_refresh` does not install a watcher |

The image contains a copy at `/app/config`; editing host files alone does not
update it. Rebuild the backend or mount a writable operator config directory
there, preserving all shipped files. Rebuild links after changing matching rules.
A writable mount is needed to persist review decisions across image replacement.

Standalone CLI: `tracekite --config-dir /path/to/config COMMAND ...`, or set
`KG_CONFIG_DIR`. Python: call `engine_config.configure(config_dir=...)` before
loading. Configuration is process-wide. Generate artifacts into a fresh output
directory when changing the engine, configuration, redaction key, or intended
revision metadata: 0.2.0 artifact reuse checks source content, not those settings.

## Authentication

Keep the default loopback bindings for local use. Before exposing the server,
set `AUTH_ENABLED=true` and a strong `API_TOKEN`, decide whether anonymous reads
are acceptable, and provide HTTPS through your deployment. This is a shared
credential, not per-user authorization. Use the browser token prompt or an
`Authorization: Bearer ...` HTTP header. See [security and privacy](security-and-privacy.md).
